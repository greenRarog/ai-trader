# AI Trader — согласованный контекст

Автономный LLM-агент для российского рынка: Go, T-Invest Sandbox, PostgreSQL,
OpenAI API, CLI, Docker Compose. Разработка идёт по этапам; реальные деньги
и торговля на реальных счетах не разрешены.

Этап 1: REST-подключение к Sandbox, явные команды создания виртуального счёта,
пополнения на 100 000 рублей, получения баланса и котировок. PostgreSQL
подключается на этапе 2 вместе с историей решений. Сделок на первом этапе нет.

Владелец согласовал два крайних режима выбора инструментов:
- protective: разрешён только заданный список;
- experimental: список не ограничивает выбор.

На первом этапе поддерживаются рублёвые акции. Плечо, шорты, фьючерсы и опционы
не разрешены. Будущие лимиты: позиция 20 000 рублей, 5 открытых позиций,
дневной убыток 3%, просадка 15%. Режим выбора не может отменять ограничения риска.

Следующие этапы: OpenAI и сохранение решений без сделок; Risk Engine и Sandbox
торговля с идемпотентностью, проверкой исполнения и комиссиями; автономный цикл
с расписанием и восстановлением; аналитика, модельные налоги и стоимость ИИ.
Telegram добавляется позднее. При портфеле 150 000 рублей предполагается
виртуальная фиксация 50 000 рублей в собственной БД; Sandbox не позволяет
списывать средства через SandboxPayIn. Реальный вывод требует решения владельца.

LLM принимает BUY/SELL/HOLD, но не меняет ограничения и не получает доступ к
выводу средств. Нужны контексты, таймауты, обработка ошибок, история решений,
точная денежная арифметика, секреты вне репозитория. Веб-интерфейс не требуется.

Результаты Sandbox не гарантируют прибыль: учитывать комиссии, проскальзывание,
налоги и стоимость OpenAI. Создание файлов первого этапа разрешено владельцем
сообщением «если вопросов нет — выполняй». Другие этапы пока не реализуются.

## Этап 2 — согласован и реализуется

Владелец подтвердил первый этап реальными вызовами Sandbox: счёт создан,
пополнен на 100 000 рублей, получены баланс/котировки, проверены оба режима.
Командой «если вопросов нет — выполняй» разрешён второй этап: PostgreSQL,
OpenAI Responses API, структурированные предложения BUY/SELL/HOLD, валидация,
история запросов/ответов/токенов/ошибок и CLI analyze без исполнения сделок.

Модель выбирает только из переданного контекста. В experimental набор кандидатов
можно расширять через --instruments, без приоритета списка. Автопоиск по всему
рынку не реализуется на этом этапе. Вводится статус validated_proposal — это
проверка структуры/режима/свежести, не разрешение на исполнение сделки.
Risk Engine, дневной убыток/просадка, комиссии и денежная стоимость ИИ остаются
следующими этапами. API-ключ OpenAI владелец заполняет локально в .env.


## Дополнение: Codex CLI вместо API-ключа

Владелец подтвердил codex-cli 0.164.0 и вход через ChatGPT; разрешил добавить
AI_PROVIDER=codex_cli без OPENAI_API_KEY. Реализуется запуск на хосте через
локальный бинарник, собираемый Docker, с PostgreSQL в контейнере. Codex
получает контекст через stdin, возвращает JSON по общей схеме, проверки и
история остаются в Go. Режим openai_api сохраняется как альтернатива. Auth-файлы
не копируются в проект/контейнер, действуют лимиты подписки Codex. Сделки
по-прежнему не исполняются. История получает колонку provider (миграция v2).


## Подготовка к виртуальной торговле

Владелец подтвердил рабочие analyze/history через Codex CLI и PostgreSQL Unix
socket. Разрешил следующий отдельный шаг: свечи/статусы/расписание, история
капитала и Risk Engine. Добавляются только read-only методы брокера, команды
market/equity/risk-check; отправка заявок остаётся выключенной.

Схема v3 сохраняет equity_samples. Дневная база — первый замер дня по Москве,
high-water — максимум замеров, минимум исходные 100 000 ₽. Дневной стоп 3%
фиксируется до следующего дня, стоп по просадке 15% сохраняется по счёту.
Внешние денежные потоки пока не корректируются; это обязательная доработка
перед будущим исполнением заявок. Risk Engine работает как preview по снимку,
проверяет деньги/акции/позиции/комиссию/ликвидность/торговый статус/календарь.
Комиссия Sandbox 5 bps, запас проскальзывания по умолчанию 20 bps. Продажи
свободных акций для снижения риска допускаются после стопов; плечо и шорты нет.

## Ручной Sandbox-исполнитель и денежные потоки (v4)

Владелец разрешил продолжить Sandbox: денежные потоки, идемпотентные заявки,
проверка исполнения и восстановление после сбоев. Добавлены trading pause/resume,
orders execute/reconcile/cancel/events и funding/cashflow journals. Реальные
счета и вывод средств не разрешены. Автономный периодический запуск пока не добавлен.

analyze остаётся без исполнения. Только отдельный orders execute по свежему
validated_proposal BUY/SELL от Codex/OpenAI может отправить Sandbox-лимитную
заявку с Fill-and-Kill и margin=false. Один analysis ID — один request UUID.
Данные и риск читаются заново до отправки. Неизвестный результат не повторяется
POST-ом: выполняется поиск исходной заявки по request ID. Журнал сохраняет
каждое состояние и сырой ответ; частичные исполнения считаются накопительно.

Отдельный счёт инициализируется из положительного RUB-остатка без позиций.
Сверка ожидаемых денег и акций блокирует необъяснимые изменения. Пополнения
через приложение сохраняются до PayIn; подтверждённые потоки корректируют
историю капитала. Неопределённый PayIn требует сверки и решения владельца,
поскольку у него нет request ID. Внешние денежные потоки классифицируются
владельцем по точной разнице с брокером, а не автоматически объявляются доходом.
Полный импорт чужих сделок, налогов и корпоративных действий остаётся отдельной
доработкой перед реальным контуром. Торговля по умолчанию на паузе, состояние
паузы и стопы риска сохраняются после перезапуска.

Предыдущие тесты и read-only интеграция подтверждены владельцем. Новые тесты v4
и фактические BUY/SELL ещё требуют выполнения на машине с Docker и доступа
к Sandbox в обычную торговую сессию.


## Экономный анализ и два дневных окна (v5)

Владелец согласовал два анализа в торговый день вместо вызовов каждые 30 минут,
сокращение контекста, фильтрацию непригодных данных, защиту от повторов и учёт
токенов. В v5 добавлены компактный общий вход Codex/OpenAI, замена стандартных
инструкций Codex короткими торговыми, local skipped, fingerprint cache 10m,
атомарное резервирование попыток до модели и лимит 2 на московский день по счёту.
Ошибки/таймауты расходуют попытку. Явный analyze --refresh обходит кэш/лимит, но
не проверки данных/паузы/риска. usage считает reported tokens без вызова ИИ;
market --compact позволяет посмотреть нормализованный вход без модели.
Полные снимки и причины пропусков остаются в истории. reused не исполняется
как новый analysis ID, а ссылается на исходную рекомендацию.

automation tick/run проверяет счёт раз в минуту, опрашивает pending-заявки без
повторной отправки, сохраняет капитал при позициях и останавливает счёт при
расхождении учёта/наблюдаемом стопе. Принудительной продажи нет. Анализ по MOEX
главной сессии через час после открытия и за час до закрытия, окно 30 минут,
без догоняющих повторов; попытка окна сохраняется до вызова, переживает рестарт.
Периодическое исполнение сделок НЕ включено. Реальная торговля по-прежнему
не разрешена. Новые Go/PG-тесты v5 требуют запуска на машине с Docker.

## Эксплуатация и публикация (v6)

Владелец разрешил реализовать аналитику, уведомления, автозапуск и резервные
копии; новый приватный GitHub-репозиторий — GreenRarog/ai-trader.
Прежний README целиком сохранён в docs/OPERATIONS.md. Новый README содержит
краткую идею, статус и команды развёртывания; дополнения v6 — docs/DEPLOYMENT.md.

Добавлен read-only report: прибыль капитала без записанных внешних потоков,
простая доходность и выборочная просадка, подтверждённые комиссии/оборот,
FIFO с покупными комиссиями и остаточной себестоимостью. Время частичных
исполнений пока приближено датой создания заявки. Неизвестная себестоимость
и известные проблемы сверки не превращаются в прибыль; итоги помечаются
неполными или не показываются. Денежные значения CLI — точные строки RUB.

Telegram опционален, выключен до настройки локальных переменных; входящих
команд бота нет. Outbox переживает перезапуск. Неопределённые отправки не
повторяются; 429 допускает ограниченные отложенные попытки. Ошибки доставки
не меняют результат операций со счётом. Токен в БД и дочерний Codex не передаётся.

Установщик служб systemd подготовлен для обычного пользователя: непрерывный
анализ и ежедневный backup с полной проверкой восстановления. Автоисполнение
заявок не добавлено. Установка требует запуска установщика на хосте; user
lingering и Docker daemon настраиваются владельцем отдельно.

Скрипты создают private custom pg_dump + SHA256, проверяют восстановление
в отдельном tmpfs-сервисе без production volumes, оставляют последние 14 копий.
Локальные архивы не заменяют независимое хранилище. При DATABASE_URL скрипт
отказывается копировать другую Compose-БД. Изолированная проверка не заменяет
план восстановления рабочего сервиса: данные поднимаются в новом томе и сверяются.

Offline-тесты операционных скриптов выполняются без настоящего Docker; Go/PG
и фактическое восстановление требуют доступа к Docker. В окружении агента
GitHub CLI отсутствует, прямые сетевые подключения к GitHub недоступны; для
публикации подготовлен scripts/publish-github.sh с проверкой секретов, приватности
и аккаунта. Факт успешного push должен подтверждаться отдельно.
