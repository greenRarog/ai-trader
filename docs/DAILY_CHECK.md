# Ежедневный контроль автономного Sandbox

После настройки достаточно оставить машину включённой, с интернетом и работающим
Docker. Служба `ai-trader.service` запускается автоматически. При выключенной
или спящей машине трейдер не работает; пропущенные торговые окна не догоняются.
После пробуждения/перезапуска служба продолжает сверку сохранённого состояния.

`AUTOMATION_EXECUTE_ORDERS=true` в `.env` включает автоматическое исполнение
свежих BUY/SELL фонового процесса. В действующей установке эта настройка включена.
Два окна анализа определяются по расписанию MOEX: через час после открытия
главной сессии и за час до её окончания; каждое длится 30 минут. Дневной лимит —
две попытки ИИ, включая ручные вызовы и ошибки. Каждую минуту проверяются счёт
и незавершённые заявки. Торговая пауза действует после перезапуска.

## Вечером

Отчёт автоматически сохраняется ежедневно в 21:15 МСК. Посмотреть его:

```bash
cd /home/green/git/ai-trader
cat .reports/latest.txt
```

Проверь дату в первой строке отчёта. Если нужен отчёт прямо сейчас:

```bash
bash scripts/daily-report.sh --save
cat .reports/latest.txt
```

Скопируй текст целиком и пришли в чат. По нему можно разобрать решения ИИ,
исполнения, причины пропусков, комиссии, прибыль/убыток, расход токенов и ошибки.
Отчёт делает свежий замер капитала и сверку с брокером; новые решения ИИ и
торговые заявки он не создаёт. Кроме `latest.txt` сохраняются файлы по дате;
повторная генерация обновляет отчёт этого дня. Все суммы заявок с суффиксом
`_nano` указаны в нанорублях: 1 ₽ = 1 000 000 000 нанорублей.

Отчёт относится к текущему московскому календарному дню до момента генерации.
Вечерняя копия не включает более поздние события; их можно посмотреть в журнале.
Строки «ТРЕБУЕТ ВНИМАНИЯ» могут содержать уже устранённые ошибки этого дня:
смотри текущее состояние и время событий. Ранние ручные тестовые сделки также
входят в отчёт за день запуска, отдельно от решений автоматизации.

## Признаки штатной работы

- `ActiveState=active`, `SubState=running`; таймеры отчёта и копирования активны.
- Автоисполнение включено, счёт инициализирован, `paused=false`.
- Свежая сверка брокера прошла, `journal_complete=true`, `issues=[]`.
- Нет зависших `unknown`/`submitting` заявок и повторяющихся `cycle_error`.
- После торговых окон появляются автоматические анализы либо объяснимые пропуски.
- Есть свежая локальная резервная копия.

HOLD и дни без сделок допустимы. После ручного вызова ИИ дневного бюджета может
не хватить на оба автоматических окна. `skipped` разбирается по `economy.reasons`:
закрытый рынок, неполные данные, пауза, лимит попыток. Отрицательный финансовый
результат сам по себе не означает неисправность программы.

## Если требуется внимание

```bash
systemctl --user status ai-trader.service --no-pager
journalctl --user -u ai-trader.service --since today --no-pager
bash scripts/trader.sh trading status
```

При неожиданном поведении остановить новые сделки:

```bash
bash scripts/trader.sh trading pause
```

Сверка уже отправленных заявок продолжится. При неизвестном исходе не создавай
новую заявку взамен старой и не пополняй счёт ради устранения расхождения.
Пришли отчёт и причину паузы. `trading resume` применяется после выяснения
причины и сверки; он не снимает сохранённые стопы по потерям.

Ручной `analyze` остаётся без исполнения. `automation tick --now` может
отправить заявку при включённом автоисполнении и расходует дневной бюджет;
для ежедневной проверки эта команда не нужна.
